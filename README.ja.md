# Fake Test Hunter

[English](README.md) | [繁體中文](README.zh-TW.md) | **日本語**

### AIに騙されるのは、もう終わりにしませんか?

AIに「テストを追加して」と頼んだとします。返ってきたのは、緑のチェックマークと40個の新しいテスト、そして自信たっぷりの要約でした。

ところが、コードをわざと壊してみると、**テストはすべて通ったまま**です。

これが偽のテストです。安全網に見えて、実際には何も守っていません。

```ts
// モックが 42 を返し、テストは……42 を検証する。
mockApi.getUser.mockResolvedValue({ id: 42 })
expect((await getUser()).id).toBe(42)

// 「存在する」。それで、正しいの?
expect(result).toBeDefined()
```

AIは「通るテスト」を書くのが得意です。しかし「失敗しうるテスト」を書くのは苦手です。このリポジトリは、そのギャップを埋める2つのスキルをエージェントに追加します。

## 内容

| スキル | 役割 |
|--------|------|
| **`fake-test-hunter`** | 読み取り専用の監査。テストと、テスト対象のソースの両方を読み、偽のテストをファイル・行番号・種類・一文の理由つきで一覧にします。サンプリングも水増しもしません。見つからなければ、見つからなかったと報告します。 |
| **`test-squad`** | 専門のサブエージェントを並列に派遣し(それぞれ独立した worktree で)、テストの削除・強化・追加を行います。その後、**メインスレッドが自分で検証**します。専門家の報告を鵜呑みにしません。 |

## テストの判定基準

次のいずれかを満たすテストは**有効**です。

- **深い**: 入力が意味のあるロジックを通り、アサーションがそのロジックの結果を検証している。
- **広い**: 正常系だけでなく、極端な値やエラーパスもカバーしている。

次のいずれかに当てはまるテストは**偽物**です。

- **自明**: コードを読まなくても答えがわかる(モックの戻り値の検証、`toBeDefined`、`assertIsNotNone`、型システムがすでに保証していること)。
- **深くも広くもない**。

## `test-squad` がAIをそのまま信じない理由

中核となる原則は、**ソースが壊れたときに FAIL するテストだけに価値がある**ということです。

そのため、追加・強化されたテストにはすべて mutation が必要です。テストが検証すると主張するロジックを書き換え、アサーションが失敗することを示し、元に戻して再び通ることを示します。そのうえでメインスレッドは次を行います。

1. 作業ツリーがベースラインに対してテストファイルの変更だけであることを確認する。
2. 全テストと静的チェックの失敗集合が、ベースラインの失敗集合の部分集合であることを確認する。
3. 各専門家の分からサンプルを選び、自分で mutation をやり直す。1つでも食い違えば、その専門家の作業はすべてやり直し。

新しいテストが現在のコードで失敗した場合、`test-squad` はアサーションを書き換えて合わせることを**しません**。バグの疑いとして報告し、判断はあなたに委ねます。

## インストール

```bash
npx skills add cainmaila/fake-test-hunter
```

## 使い方

```text
/fake-test-hunter                 # プロジェクトが実行する全テストを監査
/fake-test-hunter src/auth        # 特定のパスだけ監査

/test-squad src/auth              # 計画 → あなたが承認 → 派遣 → 検証
```

典型的な流れ: hunter を実行し、そのレポートを squad に渡し、計画を確認して承認すれば完了です。

`test-squad` は最初に対象範囲を尋ね、全体スキャンは行いません。テスト対象のソースに未コミットの変更があれば停止し、派遣の前に必ずあなたの確認を待ちます。

## 制限

- hunter は LLM によるレビューであり、mutation testing ツールではありません。一覧は有力な手がかりであって、判決ではありません。
- mutation はすべての行に届くわけではありません。`test-squad` は網羅できなかった部分を報告します。
- 専門家が増えるほど、検証のコストも増えます。
